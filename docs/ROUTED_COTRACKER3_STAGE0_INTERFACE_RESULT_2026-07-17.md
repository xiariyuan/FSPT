
This audit is a non-training gate for the new MUSR mainline. It does not reuse the historical Route-A refiner and does not read TAP-Vid-Kinetics or TAP-Vid-DAVIS.

## 2. Frozen scope

- Backbone: CoTracker3 scaled online, true-streaming execution.
- Backbone checkpoint: `baselines/cotracker/checkpoints/scaled_online.pth` resolved to the provisioned external weight.
- Development domain: frozen Kubric validation partition only.
- Sample: global video index `0` from the frozen validation manifest.
- Shape: 24 frames, 64 first-visible queries, 256×256 input and metric raster.
- Candidate count: six per point/frame: one native candidate plus five local-correlation candidates.
- Search radius: 64 input pixels around the native continuation.
- Ground truth: inaccessible to candidate generation; used only after tensor export for oracle selection and metrics.

The completed 1,144-materialized-segment Kinetics evaluation was not read, rerun, or used for tuning.

## 3. Implemented interface

The adapter exports:

```text
candidate_coords_xy_px     [N,T,6,2]
candidate_features         [N,T,6,64]
candidate_scores           [N,T,6]
candidate_valid_mask       [N,T,6]
source_ids                 [N,T,6]
state_features             [N,T,32]
native visibility/confidence components
query points and frozen GT fields for post-export auditing
```

Candidate source `0` is the native CoTracker3 online continuation. Sources `1..5` are generated by cosine search on the current-frame CoTracker3 `fnet` feature map using the point's first-visible query-frame feature as support. Non-native candidates are not generated before the query frame.

The state adapter directly accessed the real CoTracker3 online track feature:

```text
raw online_track_feat[0] shape: [1,1,64,128]
flattened point-state shape:     [64,128]
```

No support/template state was mutated.

## 4. Native parity

## 5. One-video coordinate-oracle headroom

The oracle selects the GT-nearest valid coordinate candidate after the candidate tensors are frozen. Visibility remains exactly the native CoTracker3 visibility, so OA is unchanged.

| Metric | Native CoTracker3 | Coordinate oracle | Gain |
|---|---:|---:|---:|
| AJ | 25.5874 | 34.2351 | **+8.6477 points** |
| Delta average | 36.2192 | 48.7854 | **+12.5662 points** |
| OA | 82.3237 | 82.3237 | 0.0000 |
| Mean visible-point error | 11.5232 px | 7.2788 px | -4.2444 px |
| Median visible-point error | 7.1752 px | 4.5792 px | -2.5960 px |

There were 1,095 visible post-query evaluation rows. A non-native candidate was strictly better than native on 82.56% of those rows.

|---|---:|---:|---:|
| 1 px | 8.04% | 17.08% | **+9.04 pp** |

The gain is not confined to a single coarse threshold. The candidate pool contains both fine-precision and tail-recovery headroom, which is the intended target for MUSR's multi-threshold utility and catastrophic-risk heads.

## 6. Scientific interpretation

The preregistered one-video oracle feasibility threshold was `+3.0 AJ` points. The observed `+8.6477 AJ` passes this gate materially.

This result proves only that:

1. the CoTracker3 online interface is usable;
2. a causal, query-memory local-correlation candidate pool contains meaningful coordinate headroom;
3. exact native fallback is possible;
4. a learned selector has a non-trivial target.

It does **not** prove that MUSR can recover the oracle, improve a held-out partition, or improve any external benchmark. The number is a GT-only upper bound on one frozen Kubric video and must not appear as a learned-model result.
